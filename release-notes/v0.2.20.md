bot-agent v0.2.20 is the Deploybot host agent and its catalog runner, for Linux amd64 and arm64 hosts with systemd. It is the first release signed in CI, with the release key in AWS KMS that the v0.2.19 helper already trusts.

## What is new
- **Restart or roll back on unhealthy with the image's own HEALTHCHECK** (agent-protocol v1.28). An image entry may set `on_unhealthy` to `restart` or `rollback` without its own `healthcheck`: the agent then acts on the image's HEALTHCHECK. If neither the entry nor the image has a health check, the deploy fails with a reason that says so, and `on_deploy_failure` applies as for any failed health wait. The agent tells the server it supports this with the new hello flag `image_healthcheck_policy`.
- **Upgrade the Deploybot server first.** The server must run v0.2.51 or newer before any host moves to this release: older servers refuse the new hello flag and then treat the host's programs as off (no deploys, no agent upgrades). Do not roll the server back below v0.2.51 while hosts run v0.2.20.
- `runner.toml` and the helper's privileges are unchanged.

## Download and verify
Assets: `bot-agent-v0.2.20.tar.gz` (both architectures), `SHA256SUMS` and `SHA256SUMS.sig`. `SHA256SUMS` is the file that is signed.

```bash
tar -xzf bot-agent-v0.2.20.tar.gz
cd bot-agent-v0.2.20 && sha256sum -c SHA256SUMS
cmp SHA256SUMS ../SHA256SUMS
```

The binaries are built from tag `v0.2.20` with Go 1.27.1: `CGO_ENABLED=0 go build -trimpath -buildvcs=false -ldflags "-s -w"`. The same command on the tag gives byte-identical files (`scripts/release-bundle.sh 0.2.20`).
