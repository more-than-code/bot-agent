bot-agent v0.2.19 is the Deploybot host agent and its catalog runner, for Linux amd64 and arm64 hosts with systemd. It is the bridge release: it is signed with the offline key that today's hosts trust, and its helper also trusts the new release key that GitHub Actions signs with from the next release on.

## What is new
- **Two release keys.** The helper accepts an upgrade signed by any key compiled into it: the offline recovery key and the CI release key (an AWS KMS Ed25519 key, used only by this repository's release workflow on `main` after the owner approves). Upgrade every host to this release: a host older than v0.2.19 refuses the releases after it.
- **Host env files reach only the pinned run** (from v0.2.18, which was not published on its own). An image entry that gets a host env file must run with the command and healthcheck pinned for it in `runner.toml` (`host_env_command`, `host_env_healthcheck`) and may not set its own entrypoint, user, volumes, files or env; otherwise the helper refuses the deploy as `host_env_run`. Add those lines to `runner.toml` before redeploying such an entry.
- Releases are built, tagged and published by a GitHub workflow. The build is reproducible, and `SHA256SUMS` is a byte-identical copy of the file inside the tarball.

## Download and verify
Assets: `bot-agent-v0.2.19.tar.gz` (both architectures), `SHA256SUMS` and `SHA256SUMS.sig`. `SHA256SUMS` is the file that is signed.

```bash
tar -xzf bot-agent-v0.2.19.tar.gz
cd bot-agent-v0.2.19 && sha256sum -c SHA256SUMS
cmp SHA256SUMS ../SHA256SUMS
```

The binaries are built from tag `v0.2.19` with Go 1.27.1: `CGO_ENABLED=0 go build -trimpath -buildvcs=false -ldflags "-s -w"`. The same command on the tag gives byte-identical files (`scripts/release-bundle.sh 0.2.19`).
